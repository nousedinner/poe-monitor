**行为变化和后续需人工判断的事项**

1. 历史错误冗余标记、错误名称或指纹没有自动修复。其原始交易详情并不完整，不能把所有旧冗余标记简单翻回有效，也不能把今天的物品词缀覆盖到旧事件上。
2. 当前 sold 仍表示“从完整的当前可见结果中消失”。撤单与成交无法仅凭交易列表区分。是否改成“疑似下架/售出”、增加置信度或延迟确认，需要产品口径确认，本轮不自行增加事件类型。
3. 账号普通装备按指纹衔接变化后的 ID，跨扫描消失后重现按原 24 小时窗口修正历史；技能石按原后端 10 分钟窗口修正。原前端冗余清理跳过技能石是另一层规则，不等于旧后端也跳过；本次没有自行统一这两层规则。
4. 改变最低价或筛选条件后，下一次完整扫描重建基线，不把新旧不同条件的结果相互差分。修改间隔与排序不会重建基线。
5. 未被面板读取的旧 DailyStats 混币种任务不再运行，旧表保留；面板继续从 Event 按币种统计。
6. 线上端口与容器仍保持原部署状态。本次修复的是代码与部署模板，实际关闭 VPS 公网 5000、切换两个服务及迁移数据库，要在之后授权部署时执行。

**升级与回滚**

新代码需要先执行 `python manage.py upgrade`，API 导入不会自动建表或迁移。迁移预检查重复快照，遇到重复立即退出，不擅自删行；各步可重复执行，全部完成才记录版本。MySQL DDL 会自动提交，升级前必须有数据库备份与可恢复的旧环境。

已有 VPS 使用共享 MySQL 与 host 网络，应采用 `backend/docker-compose.host.yml`，保留原 DATABASE_URL 和三类密钥；该文件不会创建或接管 MySQL。新安装才使用自带 MySQL 的 `backend/docker-compose.yml`。这两份配置不能混用启动同一后台任务。

部署前暂停旧 PoE 单体容器中的扫描，保持共享 MySQL 及其他项目不动；新版只有 worker 执行扫描。API 与 worker 必须连接同一数据库。整个 frontend 目录都需同步，包含 ui_helpers.js 和 vendor；不能只更新 HTML。

价格列升级到 DECIMAL，不能保证旧 Integer 代码直接运行时保持小数语义。需要回滚时，应恢复匹配的数据库备份和旧镜像，或先准备经过验证的兼容版本。已有账户密码与 Cookie 加密格式保持兼容，不要重新生成线上密钥。

测试结果与边界见根目录 VALIDATION.md。测试使用本地隔离数据库、合成账户和受控上游，没有用过期凭证向腾讯发起验证。
