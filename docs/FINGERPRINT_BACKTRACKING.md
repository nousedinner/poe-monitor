指纹回溯恢复与原注释核对
======================

本次按用户要求撤回 0d0689f 中取消指纹回溯的有关改动，保留其余修复。事件 `sold` 表示观察到物品消失；重新上架会改变 ID，因此它可以被原有重挂回溯修正。不能把撤销这类观察事件直接定性为删除真实成交。

**恢复范围**

- 账号普通装备：相邻扫描可按相同指纹衔接不同 ID；多件相同指纹使用集合保留数量，不恢复旧单值字典覆盖问题。
- 账号回溯：普通装备 24 小时，技能石 10 分钟，保持原后端窗口；同价同币种撤销最近 sold，改价或改币种将其改写为 price_change。金额小数、币种识别等其他修复保留。
- 回溯改写保留原事件编号、旧物品 ID 和时间，与旧后端相同。当前快照更新为重新上架的新 ID。
- 全服监控继续按 ID 比较，不新增指纹回溯，不处理用户已排除的前 100 窗口问题或上游 401。
- 首页自动写回冗余标记的移除属于另一项修复，不随本次后端回溯撤回；前端的技能石独立显示保留。

**用户说明的业务前提**

同一件装备重新上下架时，listing ID 与 item.id 都可能变化。此前仅验证最后一轮快照里两字段相同，不能证明跨上下架的稳定性。现在在代码中明确记录此原因，避免再次用未经证实的“稳定 ID”替换指纹规则。
